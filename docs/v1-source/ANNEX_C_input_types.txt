ANNEX C — INPUT TYPE SPECIFICATIONS (v1.0)
PURPOSE: Defines every allowed Required Input type. No other types permitted in v1.0.

C.1 INPUT TYPE DEFINITIONS:

TYPE	        UI LABEL	          DESCRIPTION	           VALIDATION REGEX	          ACCEPTED FORMAT	                EXAMPLES	         INVALID EXAMPLES
none	        None / No Input Required  No typed input expected	N/A	                        N/A	                        (no value field)	       N/A
com_frequency	COM Frequency	          Radio frequency	   ^[1-9][0-9]{2}\.[0-9]{1,3}$	  3 digits, decimal, 1-3 digits after	118.7, 121.900	         011.7, 118, 118,7
squawk	        Squawk Code	          Transponder code	   ^[0-7]{4}$	                  Exactly 4 digits (0-7)	        4721, 1200, 7500	 8888, 129, 47210
heading	        Heading	                  Magnetic heading	   ^[0-9]{3}$	                  Exactly 3 digits	                090, 270, 360	         90, 27, 270°
altitude	Altitude	          Altitude in feet	   ^[0-9]+$	                  Digits only, no units	                5000, 12000, 35000	 FL350, 35,000, 5000ft

C.2 GLOBAL INPUT RULES:

Validation is local only
Exact string match, case-sensitive
No trimming beyond UI sanitation
No tolerance, hints, or auto-complete

C.3 EXTENSIBILITY RULE: Adding new input types requires new schema_version and updates to all annexes.

C.4 AUTHORITATIVE STATUS: This annex is normative. Non-conforming values must be rejected.
